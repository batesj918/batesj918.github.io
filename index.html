Francis — Multi-Agent AI Orchestrator

  • 173 commits
  • 680+ automated tests
  • 4 sub-agents
  • 14 numbered builds
The Problem
General-purpose chatbots forget everything between sessions, don't know how I actually make decisions, and can't safely take real actions like publishing a product or spending money. I wanted one assistant that remembers, reasons with my own track record, and hands off real work to specialists without going off the rails.
The Solution
I designed and built Francis, a personal AI agent in Python on the Claude API. I built it in 14 numbered builds, each with its own design, build and verification pass. Francis is the orchestrator. It holds long-term memory, a 90-day plan it filters work through, and a consistent personality. It delegates to four specialist sub-agents: Herald (market research and SEO copy), Draper (design direction), Courier (Printify and Etsy publishing) and Wright, which maintains Francis itself. Every tool call goes through a layered safety system: kill switch, approval gates, rate caps, a money guard and an audit log.
Tech / Tools
Python 3, Anthropic Claude API, pytest, Three.js dashboard, server-sent events, ElevenLabs speech, Discord bot API, Printify and Etsy APIs, Replicate, Pillow, NumPy vector index, git hooks, Windows Task Scheduler.
The Impact
Francis runs day to day across the terminal, voice and a browser dashboard. It is the engine behind my Etsy shop: the sub-agents have taken listings from niche research to live on Etsy with a single approval from me in Discord. It is covered by 680+ automated tests, and a test gate blocks any push that breaks them.
Full feature breakdown26 features

Orchestrator + sub-agents

  • Sub-agent roster lives in a config file and reloads without a restart; each agent has its own prompt, tool allowlist and iteration limit
  • Herald: pulls top Etsy listings and prices for a niche, checks real production cost, writes the SEO title, exactly 13 tags and the description
  • Draper: turns Herald's themes and palettes into precise design briefs and embroidery-safe design specs, then sends them to Discord
  • Courier: uploads artwork, creates the Printify product, publishes it to Etsy, and checks status and mockups (read-only checks need no confirmation)
  • Wright: runs the test suite, repo health and git checks, compares the docs to the code, and applies small patches only after I confirm each one; key files are write-protected
  • Agent factory designed (Francis proposes new specialists when a gap appears) and deliberately held until a fifth agent is needed

Memory + reasoning

  • Recall over a 16,880-chunk index of my past AI conversations (5,791 entries), with a gate that treats recalled text as untrusted
  • Memories are pulled out automatically at the end of each session, then de-duplicated and archived by a curation pass
  • Self-knowledge doc (what files, tools and features exist) regenerates on every commit via a pre-commit hook
  • Personality drift lock keeps the voice consistent across sessions
  • Reasoning eval: a test set checks whether Francis's calls match my real decisions; mismatches were traced and fixed
  • 90-day "north star" doctrine with dimensions and operating rules that every task is filtered through, plus a scheduled daily brief

Safety + cost control

  • Kill switch that stops all tool execution instantly, checked before anything else
  • Approval modes (off / smart / manual) plus a hardline blocklist that can't be turned off
  • Per-tool rate caps (for example, publishing max 1 per hour and 4 per day) and a process-wide cap on model calls per minute
  • Money guard: refuses any listing priced below known production cost, or any product type whose cost hasn't been verified
  • Append-only audit log of every tool call; log redaction in debug mode
  • Monthly budget watch with alerts at 50%, 80% and 100%; /cost shows spend by model and prompt-cache savings
  • Pre-commit secret scan, pre-push test gate, weekly dependency vulnerability scan, and an incident runbook
  • Graceful degradation: if a service is down, Francis falls back to reduced features instead of failing outright

Interfaces

  • Terminal chat with resume, debug mode (tokens, cache, latency, tool calls) and slash commands
  • Push-to-talk voice mode with speech-to-text and spoken replies
  • Local-only browser dashboard: animated Three.js orb, live sub-agent indicators, streaming chat, and panels for heartbeat, memory, cost and self-knowledge
  • In-browser Allow/Deny cards for any action that needs confirmation, streamed live to the page
  • Discord bridge: a bot checks a studio channel every minute and acts on replies such as "approve 2", "deny" or a pasted design edit
  • Heartbeat: holds reminders and deadlines and surfaces quiet, dismissible notices at zero API cost

Crafted by Francisco — Agent-Run Etsy Shop

  • 8 live listings
  • 2 product types
  • Human-approved publishing
  • Printify print-on-demand
The Problem
Launching print-on-demand products is a pile of repetitive steps: research a niche, check prices, write SEO copy, make a design that can actually be embroidered, build the product, publish and track it. Doing it by hand is slow, and automating it carelessly can publish bad listings or products that lose money.
The Solution
I built an embroidered-apparel Etsy brand, Crafted by Francisco, and an Etsy Studio pipeline inside Francis to run it. One command finds a niche. Herald researches it and writes the copy, Draper produces design candidates that follow embroidery rules, and the candidates land in Discord. I reply "approve 2" (or paste an edited design), and Courier builds the Printify product and publishes it to Etsy. Guardrails that I can't skip enforce pricing above cost and cap how often it publishes.
Tech / Tools
Francis sub-agents (Python), Etsy + Printify APIs, Discord bot, Pillow design renderer, Replicate AI art, Canva, Zeely (AI lifestyle photos + UGC video), Windows Task Scheduler.
The Impact
The first listing went live end to end on 3 Aug 2026 from a single approval reply in Discord. The shop now has 8 live listings across dad hats and beanies, including photo- and text-personalized products, and is in a 90-day monetization test.
Full feature breakdown21 features

Brand + catalog

  • Brand identity: name, logo, 3360×840 shop banner, tagline and shop story; no licensed logos
  • 8 live listings: Custom Number, Custom Photo, Custom Name Beanie, Reel Happy (fly fishing), Sunrise Ridge, Soccer, Jokes Loading, Running on Coffee & Denial
  • Personalization in two forms: an Etsy text field (numbers, names) and a photo-upload field, with a runbook for fulfilling photo orders
  • Premium pricing ($29.86–$39.99) set against known production cost
  • Product-type registry (blueprint, provider, cost, canvas size, copy facts) so adding a product is a config change, not new code

Etsy Studio pipeline

  • Niche discovery across ~18 product spaces, ranked by traction; top 5 posted to Discord to choose from
  • Herald writes Etsy-SEO copy: title, exactly 13 tags and a description, following written SEO guidelines
  • Design generator enforces embroidery rules by construction: 1650×600 transparent canvas, ≤6 flat thread colors, minimum text height
  • AI artwork option (Playground v2.5 on Replicate, about $0.05 per image), passed through the same design checks
  • Import path: any finished PNG (Canva export, AI output, a manual file) can be added as a candidate
  • Job state machine (awaiting niche → designing → awaiting approval → approved → publishing → live), with each job's state saved to disk

Human-in-the-loop controls

  • Discord approval is the publish gate: only the bot, reading my reply, can mark a job approved
  • Reply "approve N" to pick a design, "deny" to reject, or paste an edited PNG; approving several at once from one batch is supported
  • Money guard: publishing is refused if the price is below production cost or the product type isn't verified
  • Publish caps (1 per hour, 4 per day) are re-checked inside the publish step itself
  • Append-only publish ledger records every listing that goes live
  • The Discord bridge runs every minute as a self-healing scheduled task and can't double-process a reply

Marketing creative

  • AI lifestyle scenes and fashion try-on images for every product
  • Short UGC-style hook and body video ads made from a written creative process
  • Full shop audit (SEO, tags, attributes, photos, pricing, policies) with fixes applied
  • Growth strategy doc for the shop, focused on embroidered hats as the core line

Plastic Reset

  • Web + mobile app
  • 4-app monorepo
  • Written threat model
  • Consent-first analytics
The Problem
Most people know microplastics exist, but they have no idea what their own exposure looks like and no reason to change anything. Knowing about a problem in general doesn't change behavior or lead to a purchase. A personal, concrete number does.
The Solution
I built Plastic Reset end to end, from the brand to four connected apps: a marketing homepage, a web quiz, a React Native mobile app and an API. The Microplastic Exposure Score quiz gives each person a 0–100 score across 7 categories and a shareable score card. Their highest-risk areas then route them to specific product swaps in the shop, and an email-gated 7-Day Guide feeds an email sequence.
Tech / Tools
pnpm monorepo, React/Vite, Expo (React Native), Express 5, PostgreSQL + Drizzle, OpenAPI → generated client, Zod, Brevo, Cloudflare Turnstile, object storage, unit tests, Canva.
The Impact
Live at theplasticreset.com. Real users take the quiz and share their scores, and the shop routes each person to products that fit their results. Every email subscriber is verified, and privacy and security were designed in from the start, with a written threat model. I designed, built and maintain all of it on my own.
Full feature breakdown21 features

Quiz + scoring

  • 12 plain-language questions, 7 exposure categories (drinking, cooking, food storage, clothing, personal care, air, cleaning)
  • Weighted 0–100 score with 4 risk bands (Low / Moderate / High / Critical) and each person's top exposure sources
  • Bot-resistant quiz sessions (Cloudflare Turnstile), loaded only with consent
  • Shareable result pages with auto-generated social preview images, a downloadable score card, and X / Facebook / WhatsApp sharing
  • Companion React Native (Expo) mobile app with its own consent banner

Commerce

  • Curated shop of low-plastic swaps; each product is tagged to a quiz category so results link to the right items
  • Category filter chips (Air, Food Storage, Kitchen, Water)
  • Product images downloaded and served from the site itself, never hotlinked (keeps affiliate links compliant)
  • Catalog sync: editing the product list automatically updates the database on the next request

Email + lead generation

  • Email-gated 7-Day Plastic Reset Guide (designed eBook), with the PDF served only through a gated, no-index endpoint
  • Double opt-in built in-house: signed 24-hour tokens stored only as hashes, and a confirmation page email scanners can't trigger
  • Signed, verified profile claims (name, score, risk band) sent to the Brevo list only after confirmation
  • Retry-safe: a failed send or enrollment is never reported as a success

Content + reliability

  • Homepage news strip: the 6 newest microplastics stories, refreshed hourly from Google News
  • Resolves Google News redirect links to the real publisher articles and pulls each article's image
  • Falls back to publisher RSS feeds, plus a Postgres cache so a cold start still shows content
  • Image proxy with type and size checks, an in-memory cache and branded placeholders

Privacy, security + brand

  • Consent-first: no analytics or bot checks before the visitor agrees; declining is honored everywhere
  • Written threat model covering spoofing, tampering, data leaks, abuse and admin access
  • Admin-only reporting and catalog routes, a tight Content Security Policy, and log redaction
  • Full brand kit: faceted water-drop mark, color tokens, Montserrat type, voice rules, and colors for each risk band

Live Web Product — Gaming

tracksprites.com

  • 218 variants tracked
  • 15 pages
  • 4 languages
  • Automated daily upkeep
The Problem
Fortnite's Sprites are collectibles with multiple variants and mastery levels, and it takes a lot of in-game “dust” to max them out. Each season adds new sprites and variant tiers. Epic provides no tool to track a collection, estimate costs, find codes or coordinate trades, so players were stuck with spreadsheets and Discord threads.
The Solution
I built TrackSprites, a mobile-first, installable PWA that has grown from a single tracker into a full companion app. It covers collection tracking with dust analytics, an interactive map, a code checklist, compare and squad-trade planning, leaderboards and public profiles. Scheduled AI agents keep it current each season with no manual updates from me.
Tech / Tools
React + Vite, TypeScript, Tailwind CSS, Express 5, PostgreSQL + Drizzle, OpenAPI/Orval codegen, Passport OAuth (Discord/Google/Epic), Workbox PWA, i18next, html2canvas, pnpm monorepo, Claude Code scheduled agents.
The Impact
Live on its own domain, tracksprites.com, with a real player community: top collectors on the leaderboard are tracking 200+ variants each. New in-game content, such as the Loot Hacker variant tier, reached the site the same week it appeared in the game.
Full feature breakdown21 features

Collection + analytics

  • 218 variants across two seasons (C7S3 Runners, C7S4 Override), grouped by season
  • Tap a variant to cycle its state: locked → levels 1–4 → mastered
  • Owned / Missing filters and sort by type or name
  • Dust-value panel: the total value, a breakdown by variant tier, and the priciest item
  • Dust calculator (bottom sheet on mobile, sidebar on desktop) and a Gizmo progress tracker

Player tools

  • Interactive, zoomable island map with spawn info
  • Lobby Hack code list (44 codes) with copy buttons and a redeemed checklist
  • Compare your collection with any player
  • Squad Trade: builds a plan so every player in a 2–4 person squad gets something; live trade rooms by code
  • Share links that don't require sign-in, plus export of the collection as an image
  • Strategy guide

Community + accounts

  • Season and all-time leaderboards, plus friend groups
  • Public profiles at /u/username
  • Sign in with Discord, Google or Epic; works without an account, and saved progress merges in on first sign-in
  • Discord community; lore and tips auto-posted to Discord and Facebook twice a day

Platform + operations

  • Installable PWA that works offline
  • Available in English, Spanish, French and Japanese
  • Daily scheduled AI agent checks for new codes and variants and only publishes a change once two independent sources confirm it
  • Falls back to a Replit mirror of the code when GitHub access is blocked
  • Content bank served as JSON and chosen by date, so no state file is needed; a relay endpoint handles Facebook posting
  • OpenAPI spec as the single source of truth for the API, with a typed client generated from it; written threat model

Trading Bot

  • 26+ build phases
  • 448 tests passing
  • Paper-trading first
  • Multiple signal sources
The Problem
Manually tracking trading signals and acting on them is slow and emotional. I wanted a systematic, disciplined way to test strategies, with hard limits so no impulsive call or runaway script can do damage.
The Solution
It started as a single-script Replit MVP and grew, over 26+ build phases, into a test-covered paper-trading system on Alpaca. It combines options-flow data with congressional trade disclosures (STOCK Act filings) to generate signals, submits paper-only orders, and emails a daily report. A second layer connects the official Robinhood MCP connector to a separate, dedicated cash account. There, technical indicators are passed to Claude as structured data and every trade has to clear hard guardrails.
Tech / Tools
Python, Alpaca API (paper), Robinhood MCP, yfinance, Anthropic Claude API, options-flow and congressional-trade feeds, py-clob-client (Polymarket), pytest, automated email reporting.
The Impact
A verified, test-covered system (448/448 tests passing) with confirmed brokerage connectivity, now being hardened for always-on deployment. It started as a single script.
Full feature breakdown14 features

Signals + decisions

  • Options-flow feed combined with congressional trade disclosures (STOCK Act)
  • RSI, SMA and volume from yfinance, sent as structured JSON to Claude for a scored decision
  • Researched extra signals: congressional trackers (Capitol Trades, Quiver Quantitative), 13F institutional filings and Form 4 insider trades
  • Confidence scoring for every trade idea

Risk controls

  • Paper-only order submission while strategies are proven
  • Confidence threshold: no trade below it
  • Per-trade dollar cap and buying-power check before any order
  • Separate, dedicated cash account for agent trading; the main account is read-only

Engineering + ops

  • 26+ numbered build phases, each verified before the next
  • 448-test suite; confirmed brokerage connectivity
  • Daily report sent by email, with a dashboard pipeline in progress
  • Hardening underway for always-on deployment

Adjacent experiments

  • Polymarket copy-trading bot MVP (py-clob-client SDK, Polygon) built on Replit
  • Evaluated correlated-market arbitrage, chosen over news arbitrage because of latency limits

PT Survival Kit

  • Conversion landing page

The Problem
Physical therapists are burning out. They are buried under documentation, required continuing education (CEU) credits, and pressure to stay current on the research. As a recruiter hiring PTs day to day at Professional Therapy Partners, I see this firsthand.
The Solution
The PT Survival Kit is a one-time-purchase bundle of three digital tools, each aimed at one of the biggest daily stressors. It is sold through a conversion-focused landing page that walks visitors from the problem to the tools, how they work, and bundle pricing.
Tech / Tools
React + TypeScript, Vite, Tailwind CSS v4, Radix UI / shadcn/ui, Express, Drizzle, Gumroad.
The Impact
A fully built, mobile-responsive landing page and product plan, one Gumroad listing away from being ready to sell. It draws on insight from recruiting PTs every day.
Full feature breakdown7 features

The three tools

  • Burnout Reset Planner: printable and digital weekly planner, a daily top-3 priorities system, documentation time blocks and boundary scripts
  • No-BS CEU Finder: curated, affordable, commonly accepted CEUs with online and live options, ethics-requirement filters, cost comparisons, and notes and ratings
  • Evidence Survival Kit: plain-language research summaries (what the evidence supports and what it doesn't), patient talking points and insurance rebuttal scripts
